# Part 3 Flashcards · The Body

> Ten cards on what a beat may do and touch.

| # | Front | Back |
| - | ----- | ---- |
| 1 | The body decides… | blast radius: exactly the standing room, moves, and reach the job needs — nothing more |
| 2 | Worktree decision rule | overlapping files (or failure must not poison main) → worktree; disjoint ownership → shared tree is fine |
| 3 | A worktree is… | another working directory on the same repo: same history, own branch, own files — isolation for cheap |
| 4 | The cold-start problem | every beat wakes amnesiac; spine remembers *facts*, skills remember *procedure* |
| 5 | Skill vs. plugin | skill = instructions the model follows (markdown); plugin = software the harness runs (code) |
| 6 | A skill's description must say… | *when it applies*, in the words a task would use — that's what makes it trigger |
| 7 | The three connector rules | few focused tools · idempotent writes · actionable errors |
| 8 | "Ensure X" beats "do X" because… | retries and double-fired events make idempotency the difference between once and twice |
| 9 | Maker–checker in one line | the hand that writes never approves; the grader is read-only on the work |
| 10 | A workflow is… | the body of one beat — fixed steps inside; the loop still owns whether and when |
